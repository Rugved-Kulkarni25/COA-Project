CONCEPT NOTES

How the methods work

Programmed I/O

The CPU checks the device status repeatedly. Once ready, the CPU moves each data unit. This is simple, but polling can keep the CPU busy while waiting.

Interrupt-Driven I/O

The CPU can do other work while the device prepares data. The device sends an interrupt when it needs service, and the CPU runs an interrupt service routine.

DMA

The CPU configures the DMA controller with the source, destination, and transfer size. The controller transfers the block to memory and typically interrupts the CPU when the block is complete.

ALGORITHM & ASSUMPTIONS

Simulation rules

  1. Validate the workload and timing parameters.
  2. Create one transfer operation for each data unit.
  3. Generate method-specific polling, interrupt, or DMA events.
  4. Record elapsed ticks, CPU busy ticks, and completed units.
  5. Display the event trace and calculate performance metrics.

Simplifying assumptions: one tick is an abstract time unit; transfers are sequential in this model; DMA has setup and completion-notification overhead; interrupt service has a configurable CPU cost. The model is intended to teach differences in CPU involvement, not predict a specific hardware system.
